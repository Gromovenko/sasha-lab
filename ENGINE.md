# Движок заявок и автостраниц

Два контура на одном коде и одной базе:

* **движок заявок** (`engine/`) — из обращения клиента делает готовый ответ с ценой
  и держит сделку до результата;
* **автостраницы знаний** (`seo/lib/writer.js`) — несколько раз в день смотрит, что
  спрашивают в поиске, и выпускает обоснованные страницы базы знаний.

Оба универсальны: про фары и линзы знает не код, а **отраслевой пакет** —
файл `packs/<id>.json`. Тот же движок обслуживает подбор отеля
(`packs/hotels.json` — рабочий пример, не заглушка).

---

## 1. Откуда задача

Живая переписка мастера (16.09.2026), разобранная по шагам:

| Что делает мастер | Что делает движок |
|---|---|
| читает вопрос, вытаскивает машину и «нужны обманки» | `extract.js` — разбор переписки в структуру |
| смотрит фото: «там места мало под новую линзу» | `vision.js` — Qwen на neuraldeep, находки из пакета |
| «пойдёт только линза с маленьким радиатором» | `rules.js` — находка сужает каталог (`requireTags: compact`) |
| считает 45 000 + обманка 5 000 + рамка 1 500 | `quote.js` — смета кодом, не моделью |
| «переделываю ответ», пишет КП | `offer.js` — новая ревизия черновика с пометкой «уточнено по фото» |
| отвечает через час, «80% в пустоту» | панель `/crm` в телефоне + напоминания через 4 и 48 часов |

Сквозной прогон этого диалога зафиксирован тестом
(`test/engine.test.js` → «полный путь: вопрос без фото → фото меняет ответ → отправка → напоминания»).

## 2. Как устроено

```
канал (telegram / avito / whatsapp / форма сайта / вручную)
        │  engine/channels/*
        ▼
  ingest ──► deals + deal_messages + uploads/            приём: сделка одна на чат
        ▼
  extract ─► subject по схеме пакета (эвристики + Qwen)  чего нет — не выдумываем
        ▼
  vision ──► findings из списка пакета (только Qwen, РФ) смотрим ТОЛЬКО новые фото
        ▼
  rules ───► план: доп. позиции, сужение каталога, вопросы, примечания
        ▼
  quote ───► смета: варианты + дополнения + «что входит» + итог   ← считает КОД
        ▼
  offer ───► текст по шаблону пакета (+ сторож цифр)      → deal_drafts (ревизии)
        ▼
  панель /crm: отправить / скопировать / пересчитать / цены
        ▼
  send ────► канал + план напоминаний (deal_followups)
```

Правила, которые стоит держать в голове при правках:

* **цену считает код.** Модель разбирает текст и смотрит фото. Всё, что касается
  денег, проходит через `quote.js` и шаблон. Если модель когда-нибудь будет
  причёсывать текст (`offer.guardPolish`), правка с изменённой цифрой выбрасывается.
* **зрение — один движок, Qwen на neuraldeep.** Фото клиента (двор, номер машины)
  за периметр РФ не уезжают. Нет ключа — честная пометка «нужен взгляд мастера»,
  а не тихая подмена другим сервисом.
* **не молчим и не выдумываем.** Не хватает данных — уходит вопрос, а цена всё
  равно считается по тому, что известно (клиент видит цифру сразу, как у
  «больших сервисов, где сидят админы»).
* **отправляет человек.** `ENGINE_AUTOSEND=off` по умолчанию. `questions` —
  уточнения уходят сами, цена ждёт мастера; `all` — движок отвечает сам.

## 3. Новая отрасль за один файл

`packs/<id>.json` — единственное, что нужно написать:

| Раздел | Что задаёт |
|---|---|
| `subject.fields` | поля объекта заявки (машина / поездка / техника), `required` — без чего не считаем |
| `wants` | слова клиента → теги каталога («полиров…» → `polish`) |
| `photos.checklist` | какие кадры просить |
| `vision.instruction` + `vision.findings` | что искать на фото и что каждая находка меняет |
| `catalog` | позиции: `item` — варианты клиенту, `option/work/fee` — дополнения |
| `rules` | условия → решения (`addItem`, `requireTags`, `note`, `ask`) |
| `offer` | шаблон КП (`{{#choices}}`, `{{#extras}}`, `{{#includes}}`, `{{total}}`) |
| `followups` | через сколько часов и что напомнить |

Проверить и посмотреть результат без базы и без ключей:

```bash
node engine/cli.js packs                       # проверка всех пакетов
node engine/cli.js demo --pack hotels --text "Нужен отель у моря с детьми"
node engine/cli.js demo --finding tight_space  # как фото меняет ответ
```

Ошибка в пакете (ссылка на несуществующий sku, тег, которого нет ни у одной
позиции) ловится проверкой, а не клиентом: `packs` и тест падают.

## 4. Автостраницы знаний

`node seo/cli.js autopages --limit 2` — берёт верх очереди «нужна своя страница»
из сео-памяти и пишет страницы. Три ворот:

1. **обоснование** — материалы студии + разобранные факты `fitment` + отвеченные
   вопросы людей. Нет фактов → фраза остаётся в очереди (пустая страница вредит
   всему домену: scaled content abuse);
2. **проверка** — в тексте не может быть числа, которого нет в обосновании
   (кроме годов), нет воды, есть подзаголовки, длина 1200–9000 знаков;
3. **решение** — сама публикуется только страница с двумя независимыми фактами,
   остальные ждут кнопки владельца в `/seo` (раздел «Автостраницы ждут решения»).

Расписание: `scripts/seo-autopages.sh` (09:00, 15:00, 21:00 МСК) — дешёвый цикл
спроса (`demand --cheap`: Вебмастер + Search Console, без платного Wordstat) и
две страницы за заход. Wordstat остаётся в недельном `harvest-cron.sh`.

## 5. Что нужно подключить (только ключи, кода не требуется)

Всё кладётся в `seo/.env` на сервере (шаблон — `seo/.env.example`).

| Ключ | Что включает | Где взять |
|---|---|---|
| `NEURALDEEP_API_KEY` | разбор переписки и зрение по фото | тот же ключ, что у lifeprotocol |
| `TELEGRAM_BOT_TOKEN`, `MASTER_CHAT_ID` | приём заявок в телеграме + уведомление мастера с готовым ответом | @BotFather; chat_id — из `getUpdates` |
| `RESEND_API_KEY`, `RESEND_FROM` | ответы почтой (заявки с сайта) | Resend, домен уже подтверждали в других проектах |
| `AVITO_CLIENT_ID/SECRET/USER_ID` | Авито-мессенджер | кабинет Авито → Настройки → API |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID` | WhatsApp Cloud API | Meta Business |
| `CRM_PASSWORD` | вход мастера в `/crm` | придумать |

Без ключей движок **не встаёт**: разбор идёт на эвристиках, ответ готовится
полностью, а отправка переходит в ручной канал — мастер жмёт «скопировать» в
карточке и вставляет текст в чат площадки. Это рабочий режим, а не заглушка.

Авито и WhatsApp написаны по документации и **на живых ключах не проверялись** —
при подключении первым делом прогнать `node engine/cli.js channels` и одно живое
сообщение.

## 6. Раннбук (RU, `/opt/sasha-lab`)

```bash
node db/migrate.js                 # 003_deals.sql: сделки, переписка, каталог
node engine/cli.js sync            # налить каталог пакета (цены из базы не перетираются)
pm2 restart sasha-lab              # сайт + панель /crm + форма /zayavka
pm2 start engine/worker.js --name sasha-lab-engine   # только если есть TELEGRAM_BOT_TOKEN/Авито
crontab -e -u sashaweb             # 0 6,12,18 * * * /opt/sasha-lab/scripts/seo-autopages.sh
                                   # */15 * * * * /opt/sasha-lab/scripts/engine-cron.sh
```

Проверка выката — не «curl / == 200», а путь целиком:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<адрес>/zayavka/    # форма отдаётся
node engine/cli.js lead --text "линзы на рио 2015" --channel web     # сделка завелась
node engine/cli.js deals                                             # и посчиталась
```

Появился новый pm2-процесс или порт → **обновить `gromdash/system.manifest.yaml`
в том же заходе** (правило репозитория).

## 7. Данные и право

* `uploads/` (фото клиентов) и `seo/data/*.json` — **не в git**, не в rsync с EU;
  сделки, переписка и контакты живут только на RU (152-ФЗ).
* Переписка и фото уходят только в neuraldeep (GPU в РФ). Больше никуда.
* В базу знаний публикуется только текст студии. Чужие статьи (`documents`) —
  сырьё для фактов и никогда не контент.
* Напоминания не уходят тому, кто ответил последним, и тем, у кого сделка
  закрыта («отказ» снимает план) — иначе это спам, а не догон.

## 8. Чего осознанно нет

* **записи в календарь и оплаты** — следующий шаг после живых каналов;
* **автоответа по умолчанию** — цена это обязательство, кнопку жмёт мастер;
* **дообучения на переписке** — пакет правится руками, это конфигурация бизнеса,
  которую проверяют глазами, а не статистикой;
* **распознавания голосовых** — у клиентов Авито их не бывает, у телеграма будет
  (тот же neuraldeep ASR, что в lifeprotocol), когда появится спрос.
